# SRE Diagnosis V2 评分规则

V2 同时报告“官方答案匹配”和“证据支持的诊断质量”，避免把 Ground Truth 歧义或实体命名差异全部归因于模型。

## 总分

| 维度 | 分值 | 主要判断 |
| --- | ---: | --- |
| 触发源识别 | 25 | 是否找到最早可验证的外部变化或注入点 |
| 技术瓶颈识别 | 10 | 是否识别实际承压或失效的组件与资源 |
| 因果传播链 | 15 | 触发源、瓶颈和症状之间的机制是否完整 |
| 时间一致性 | 10 | 原因是否早于结果，是否区分多个事故阶段 |
| 证据质量 | 15 | 是否有可复核路径、时间、数值及至少两类数据 |
| 五层调查覆盖 | 10 | 系统、请求、用户、配置、业务是否均检查或声明不可用 |
| 竞争假设处理 | 5 | 是否主动寻找反证并保留无法排除的假设 |
| 修复与验证 | 5 | 是否分别处理触发源和瓶颈，并给出验证方法 |
| 输出与可复现性 | 5 | Schema、运行记录、输入 manifest 和基础设施是否正常 |
| **总计** | **100** | |

## 双轨结论

每个 Case 必须同时给出：

1. `ground_truth_match`：与官方根因实体、条件和传播链的严格匹配结果。
2. `evidence_quality`：不依赖官方标签，评价 Agent 的结论是否被当前 Case 数据支持。

可能出现：

```text
官方根因未命中，但技术瓶颈和证据链正确。
官方根因命中，但证据不足或时间关系错误。
当前数据不足以独立推导官方根因。
```

上述情况必须分别记录，不得压缩为单个成功或失败标签。

## 失败分类

- `DATA`：数据缺失、时间窗口不完整、基线不足或标签歧义。
- `PARSING`：TSV、嵌套 JSON、指标或 Trace 解析错误。
- `RETRIEVAL`：关键证据存在但未检索到。
- `REASONING`：发现证据但因果归因错误，或把瓶颈/症状当根因。
- `ENTITY`：概念正确但 Kind、namespace、name 或别名不一致。
- `OUTPUT`：JSON 或 Schema 不合法、文件未生成。
- `INFRA`：模型、代理、限流、超时、进程或沙箱故障。
- `GRADER`：评分逻辑或实体归一化与 Ground Truth 不一致。

## 强制降级规则

- 原因发生时间晚于其解释的症状：时间一致性不得分，触发源不能判为正确。
- 未检查请求维度和配置/发布维度就把资源饱和判为根因：触发源识别不得分。
- 没有至少两类独立证据：`diagnosis_status` 不应为 `resolved`。
- 只命中告警对象，没有解释上游原因：只能计算症状识别相关得分。
- Ground Truth 在当前数据中不可推导：标记 `DATA/GRADER ambiguity`，单独报告，不把全部责任计入 Agent。

## 运行指标

每次运行另外记录但不直接计入诊断准确性：

- 工具调用次数和各工具分布；
- 输入、输出、缓存和 reasoning token；
- 总耗时；
- 解析和 Schema 重试次数；
- API 错误、429 和基础设施成功率；
- 中间文件数量与大小；
- 实际扫描的数据量。
